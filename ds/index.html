A reference for the core components and patterns used across the case-management prototypes — foundations, form controls, status language, and the workflow-specific pieces (case card, swim lane, progress timeline, editable drawer).

The accent color is reserved. Use --accent only on: primary buttons, the progress-timeline current node, the state-row active marker, and checkbox / radio fill. Keeping the accent scarce keeps it "special."

Checkboxes

V7: every checkbox in the app uses a custom appearance:none treatment so the rendering is consistent across browsers and the check stays white. Locked to a true 16×16 square via aspect-ratio, min/max-width, and a flex shorthand so flex parents can't stretch the box. Containers that pair a checkbox with a text label use a 16px gap.

States
Multi-select dropdown — .ms-option

Used by the cases-filter dropdowns and the Include Disclaimers picker. 16px gap between box and label.

Rules
  • Shape: true 16×16 square. Use aspect-ratio: 1 / 1 + min-width/max-width: 16px + flex: 0 0 16px + padding: 0 so nothing inflates the box.
  • Color: white fill with a --cool-gray-3 1.5px border when unchecked. On :checked, fill flips to --accent with a white SVG check (data URI). Don't rely on accent-color — some browsers leave the check mark black.
  • Gap to label: 16px in .ms-option. Keep similar breathing room in any new container (avoid < 14px).
  • Read-only drawers: the .sp-drawer.is-readonly transparency rule excludes input[type="checkbox"], so checkboxes inside a read-only drawer remain visible (border + fill intact) while pointer-events: none blocks toggling.
  • Form-row scoping: .form-row input styling (border, padding) only targets text-shaped inputs. Checkbox + radio inputs are excluded with :not([type="checkbox"]):not([type="radio"]).

Customer-facing pills

Customers (sales rep, surgeon, sales manager) see a trimmed status set. The Blocked status is relabeled Action Required in customer copy — same .is-blocked token, different label — so the wording reads as a clear CTA. Internal-process statuses (In Process / Rework / Review) are suppressed on customer pills; only the statuses a customer needs to act on are visible.
